## Об этом модуле

`Nantuc.Cli` — это точка входа для работы с платформой Nantuc из командной строки. Модуль является тонкой обёрткой над публичным API `Nantuc.VmApplication` и предоставляет четыре основные команды:

- **compile** — компиляция исходных файлов проекта (MiniC / NANASM) в бинарный образ `program.bin`;
- **run** — загрузка и исполнение скомпилированной программы в эмуляторе виртуальной машины;
- **disasm** — дизассемблирование бинарного образа обратно в текстовое представление;
- **lib** — управление библиотеками инклюдов (добавление, удаление, проверка существования, список).

CLI не содержит собственной логики компиляции или исполнения — все операции делегируются соответствующим сервисам из `Nantuc.VmApplication` и `Nantuc.Compiler`. Задача модуля — разобрать аргументы командной строки, настроить файловый сервис и пути проекта, вызвать нужный сценарий и вывести результат (или ошибку) в консоль.

Модуль таргетит `net10.0` и использует `Testably.Abstractions` для абстракции над файловой системой, что позволяет тестировать команды с `MockFileSystem`.

## Установка

Модуль поставляется как **NuGet-пакет** и предназначен для установки в качестве глобального инструмента `.NET` (`.NET tool`). В проекте включён `<PackAsTool>true</PackAsTool>`, поэтому после публикации пакет можно установить командой:

```bash
dotnet tool install --global Nantuc.Cli
```

После установки в системе появится команда `nantuc`:

```bash
nantuc help
```

Обновление до последней версии:

```bash
dotnet tool update --global Nantuc.Cli
```

Удаление:

```bash
dotnet tool uninstall --global Nantuc.Cli
```

> **Примечание:** для установки требуется .NET SDK (или runtime) версии 10.0 или новее, поскольку проект таргетит `net10.0`.

## Ключевые компоненты

- **`CliApplication`** — центральный диспетчер команд. Принимает `ILibraryFileService`, `IProjectFilesConfig` и два `TextWriter` (output и error). В методе `Run` разбирает первый аргумент как имя команды и передаёт остальные аргументы соответствующему обработчику.
- **`ProjectsPathsConfig`** — реализация `IProjectFilesConfig`. Определяет `BaseDirectory` (текущая рабочая директория), `ProjectPath` (совпадает с `BaseDirectory`), `IncludePath` (задаётся при создании; по умолчанию `AppContext.BaseDirectory/include`) и списки расширений для ассемблера и MiniC.
- **`FileSystemLibraryFileService`** — реализация `ILibraryFileService` поверх `IFileSystem`. Обеспечивает чтение/запись файлов проекта и инклюдов, а также управление библиотеками (добавление, удаление, проверка существования, список).
- **`CLIHelper`** — набор статических утилит для разбора аргументов: поиск флага (`HaveFlag`), извлечение значения по флагу (`TryGetArgByFlag`), преобразование строки в байты (`GetBytesFromText`).
- **Команды** (`CompileCommand`, `RunCommand`, `DisassembleCommand`, `LibCommand`, `ErrorCommand`) — инкапсулируют логику конкретного сценария. Каждая команда имеет статический метод `TryCreate` (кроме `ErrorCommand`), который проверяет обязательные аргументы и создаёт экземпляр, либо возвращает `false` и пишет сообщение об ошибке.
- **`Program.cs`** — собирает приложение: создаёт `RealFileSystem`, `ProjectsPathsConfig` с путём к `include` рядом с исполняемым файлом, `FileSystemLibraryFileService` и запускает `CliApplication`.

## Команды и параметры

### compile

Компилирует проект в бинарный файл `program.bin` и сохраняет его в указанную директорию.

**Обязательные параметры:**
- `-s`, `-sv`, `-save <dir>` — директория, в которую будет записан `program.bin`.

**Опциональные параметры:**
- `-o`, `-opt` — включить оптимизации (AST + peephole).

**Поведение:**
- Без флага оптимизации вызывается `Compile` и результат сохраняется как есть.
- С флагом оптимизации вызывается `CompileToIL`, затем `OptimizationIL` (5 проходов) и `Build`.
- При ошибках компиляции выводит их в поток ошибок и возвращает код `-1`.

**Пример:**
```bash
nantuc compile -s bin -o
```

---

### run

Загружает бинарный файл в эмулятор виртуальной машины и исполняет его.

**Обязательные параметры:**
- `-p`, `-prog <file>` — путь к файлу `program.bin` (или другому образу).

**Опциональные параметры:**
- `-ram`, `-ram-size`, `-r <size>` — размер RAM (по умолчанию `1MB`). Допустимые значения: `64B` … `2GB`.
- `-ps`, `-port-size`, `-port <size>` — размер порта (по умолчанию `1KB`). Допустимые значения: `64B` … `512KB`.
- `-dps`, `-device-per-port`, `-device-on-port <size>` — количество портов на устройство (по умолчанию `16B`). Допустимые значения: `8B` … `256B`.
- `-l`, `-limit <N>` — максимальное количество шагов выполнения (по умолчанию без ограничения).
- `-t`, `-timer`, `-lt` — вывести затраченное время и количество шагов по завершении программы.

**Поведение:**
- Создаёт `VmEmulatorBuilder`, настраивает размеры портов и RAM.
- Регистрирует устройство VM (`DeviceSpec.Create(ram)`) и устройство ввода-вывода `SynchronousIOStream`.
- Загружает программу по адресу 0. При ошибке загрузки выводит сообщение и возвращает `-1`.
- Запускает программу с опциями `LaunchOptions`. Если статус завершения не `EndProgramm`, выводит информацию о сбое.
- Возвращает значение регистра `r0` как целое число.

**Пример:**
```bash
nantuc run -p bin/program.bin -ram 4MB -l 100000 -t
```

### disasm

Дизассемблирует бинарный образ в текстовое представление.

**Обязательные параметры:**
- `-f`, `-file <file>` — путь к бинарному файлу.

**Опциональные параметры:**
- `-cs`, `-codes <N>` — количество байт для дизассемблирования (по умолчанию размер файла).
- `-s`, `-save <dir>` — сохранить результат в `<dir>/result-decompile.txt` вместо вывода в консоль.

**Поведение:**
- Читает файл, преобразует текст в байты (Latin1), вызывает `StringDisassembler.Disassemble`.
- Если `savePath` не задан, выводит текст в консоль; иначе сохраняет файл и сообщает путь.

**Пример:**
```bash
nantuc disasm -f bin/program.bin -cs 64 -s out
```

### lib

Управление библиотеками инклюдов.

**Действия:**

| Действие | Аргументы | Описание |
|----------|-----------|----------|
| `add`    | `<name> <content>` или `-p <file>` | Добавить инклюд из строки или из файла. |
| `remove` | `<name>` | Удалить инклюд по имени. |
| `exist`  | `<name>` | Проверить существование инклюда. Возвращает код `0` (да) или `1` (нет). |
| `list`   | — | Вывести список всех инклюдов. |

**Примеры:**
```bash
nantuc lib add -p ./extra.inc
nantuc lib add mylib "int foo() { return 42; }"
nantuc lib list
nantuc lib exist mylib
nantuc lib remove mylib
```

---

### help

Выводит справку по всем командам и параметрам.

```bash
nantuc help
```

## Примеры использования

1. **Скомпилировать проект с оптимизацией:**
   ```bash
   nantuc compile -s ./bin -o
   ```

2. **Запустить программу с ограничением шагов и таймером:**
   ```bash
   nantuc run -p ./bin/program.bin -ram 8MB -ps 4KB -l 500000 -t
   ```

3. **Дизассемблировать первые 128 байт и сохранить результат:**
   ```bash
   nantuc disasm -f ./bin/program.bin -cs 128 -s ./out
   ```

4. **Добавить инклюд из файла и проверить его наличие:**
   ```bash
   nantuc lib add -p ./print.minic
   nantuc lib exist print.minic
   ```

## Зависимости

`Nantuc.Cli` ссылается на:

- **`Nantuc.VmApplication.Extensions`** — предоставляет `VmHostProjectBuilder`, `VmEmulatorBuilder`, `CompilationResult`, `DeviceSpec`, `SynchronousIOStream`, `StringDisassembler` и другие типы, необходимые для компиляции, исполнения и дизассемблирования.
- **`Nantuc.Compiler`** (транзитивно через `VmApplication.Extensions`) — компилятор MiniC и ассемблер.
- **`Nantuc.Kernel`** (транзитивно) — ядро виртуальной машины.
- **`Nantuc.Common`** — общие типы (`RamSize`, `PortSize`, `DevicePortSize`, `BiosStatus`, `RegType` и т.д.).
- **`Testably.Abstractions`** — абстракция файловой системы для тестируемости.

## Особенности реализации

- **Путь к инклюдам по умолчанию** — `AppContext.BaseDirectory/include`. Директория создаётся при старте, если её нет.
- **Проект и инклюды** — `FileSystemLibraryFileService` при чтении файла сначала ищет его в `IncludePath`, затем в `ProjectPath` (текущая рабочая директория).
- **Кодировка** — файлы проекта и инклюдов читаются и пишутся в UTF-8. Бинарные образы преобразуются в/из строки с кодировкой Latin1 (побайтовое соответствие).
- **Коды возврата** — команды возвращают `0` при успехе, отрицательные значения при ошибках (например, `-1` при ошибке компиляции или исполнения, `-2` при неверных аргументах, `-3` при неизвестной команде). `lib exist` возвращает `1`, если инклюд не найден (это не ошибка, а результат проверки).
- **Оптимизация** — при `compile -o` используется `VmCompilerOptimizator` со стандартными наборами правил AST и peephole, затем 5 проходов `OptimizationIL`.
